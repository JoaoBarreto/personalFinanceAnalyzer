Passagens de usabilidade são scripts puppeteer num contentor node (ver histórico), sem testes automáticos de UI.
Categorizar em lote (fluxo principal do utilizador: importar o ano todo e categorizar uma vez cada comerciante): em «Por categorizar» a regra aplica-se por omissão a TODAS as linhas já importadas (`aplicar_retroativamente=true`; manuais nunca são tocados); `POST /api/rules/preview-impact?linhas=N` devolve as linhas afetadas antes de clicar; `bulk-categorize` aceita `excluir_ids` e devolve `alteradas` (com o estado anterior) e `regra`; `POST /api/transactions/restore` desfaz tudo e apaga a regra criada. O painel «Última ação» permite corrigir linha a linha.
Sobreposição de extratos (ex.: anual até hoje + novembro que repete os primeiros dias): deduplicação por multiset `(conta, data_movimento, montante)` refinada por `saldo_apos`, validada em `tests/test_balances_and_views.py` (anual→novembro, novembro→anual, dia cortado a meio). Risco conhecido: se o banco alterar a data de um movimento entre exportações, a chave não coincide; os avisos de continuidade e a cobertura apanham-no. Em «Por categorizar», `version` refresca as listas de linhas dos outros grupos após cada ação.
**Importação ESTRITA (decisão do utilizador):** o parser só aceita o modelo exato do export do Bankinter (UTF-8, separador «,», colunas exatas, datas dd-mm-aaaa, montante/saldo com vírgula decimal, 2 casas e sem milhares, moeda EUR, datas dentro do período do cabeçalho). Qualquer desvio é RECUSADO (422, importação em estado `erro`, nada gravado) com mensagem agregada por tipo de problema e a indicação de usar o ficheiro original sem o guardar noutra aplicação. Nunca adivinhar o formato. Motivo: um CSV guardado por outra aplicação trazia `-889.50`, lido como -88950; a reconciliação de saldos não apanha escalas uniformes. Testes em `test_bankinter_csv.py` (secção «Modelo estrito»); o gerador `build_csv(..., estilo=)` produz formatos inválidos de propósito.
Categorias: página `/categorias` (criar, subcategoria, renomear, ativar/desativar, apagar só se sem uso), as categorias-pai também são escolhíveis («Impostos e taxas (geral)»), e cada grupo em «Por categorizar» mostra as suas linhas a pedido.
Reposição de dados: `python -m app.cli reset-movements --username U [--yes]` (`services/reset.py`; `make reset-data USERNAME=U`) apaga os movimentos e importações DESSE utilizador e mantém categorias/regras/contas/utilizadores. As categorizações MANUAIS ficam guardadas linha a linha em `categorizacoes_guardadas` (conta + data + descrição normalizada + categoria; migração 0004) e reaplicam-se, exatamente, quando a mesma linha é reimportada (`services/saved_categorization.py`, chamado no confirm antes de regras/histórico), incluindo exceções (mesma descrição, categorias diferentes). O mesmo acontece ao REVERTER uma importação (as escolhas manuais não se perdem). A resposta do confirm traz `categorizacoes_restauradas`. O preview avisa quando ≥5 linhas e ≥30% coincidem em data+descrição com movimentos gravados mas com montantes diferentes (mesmo extrato com valores diferentes: a dedup não o apanha).
**Formato principal: .xls original do Bankinter** (decisão do utilizador, para evitar conversões): `parsers/banks/bankinter/xls_export.py` (xlrd) lê a folha, converte cada linha para o texto canónico do CSV e aplica as MESMAS regras estritas (`parse_rows`). Montantes lidos por cêntimos inteiros (nunca `Decimal(float)`). Recusa: datas do Excel, montantes em texto, >2 casas, >1 folha, colunas alteradas, .xlsx. `BankinterParser` despacha por conteúdo (assinatura OLE `d0cf11e0a1b11ae1`); ids `bankinter` e `bankinter_csv` (alias) apontam para o mesmo parser. `scripts/check_xls.py` valida um ficheiro real sem mostrar valores. ## Commands

- `make test` — pytest em `backend/` (usa `backend/.venv`; a máquina é Fedora atómica com Podman, sem docker; `podman-compose` está em `backend/.venv/bin`, usar `make up COMPOSE="podman compose"` com esse bin no PATH).
- `make test-db` — corre toda a suite, incluindo testes com BD, contra um Postgres descartável (`TEST_DATABASE_URL`); `make test` salta os testes com BD.
- `make lint` — ruff.
- `make install` / `scripts/install.sh` — instalador interativo (ver README); `make reset-data USERNAME=ana` repõe os movimentos de um utilizador.
- `make create-user USERNAME=ana NOME="Ana"` — cria o utilizador dentro do contentor (pede a password).
- Migração: `cd backend && DATABASE_URL=postgresql+psycopg://... .venv/bin/alembic upgrade head`. Testada contra `docker.io/library/postgres:16` via `podman run`.
- Testes: CSV sintético gerado em `backend/tests/conftest.py` (sem dados pessoais; constantes escritas à mão). Exports reais ficam em `backend/tests/fixtures/local/` (ignorado pelo git; `test_local_real.py` verifica a reconciliação se existirem). **Nunca fazer commit de `dados.csv` nem de extratos reais.**

## Agent setup

- Main session runs on Sonnet 5.5 with Opus 5.5 as the advisor (`.claude/settings.json`).
- Read-only Haiku 5.5 subagents in `.claude/agents/`:
  - `search` — map the repo (layout, entry points, how modules connect).

## Advisor rule

Call the `advisor` tool:
1. Before locking in a plan.
2. After hitting the same error twice.
3. Before declaring a task done — write/save the deliverable first, then call it.
